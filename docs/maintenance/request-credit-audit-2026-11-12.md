## 修复覆盖

- Loomy、小浣熊、QwenWork 的流式和非流式日志保存明确的 `usage.credit` / `usage.points_consumed`。
- 流式分段 usage 合并，保留较早事件中的扣费字段，避免被末尾 token 统计覆盖；按最终累计字段记录，不逐块累加导致重复收费。
- Qoder 国内/国际从 COSY body 包装中收集 usage，保留到转换后的 Chat 响应及请求日志。
- TraeWork 解析 token_usage 时保留明确的单次积分字段，不拿账户余额或额度包用量当作本次扣费。
- Responses 的 JSON/SSE 共用用量转换保留积分扩展字段；日志仍由底层渠道统一记录。
- 新日志区分真实 0 和未返回：缺失积分存 SQL NULL，日志列表及仪表盘最近请求显示“未返回”。账户已统计积分不受 NULL 污染。
- Loomy、小浣熊、QwenWork 在收到部分积分统计后发生读取错误时，保留已经收到的用量；不据此推算缺失部分。
- 修复 Responses 流式客户端读到 `[DONE]` 即关闭时的结束处理：Loomy 不再误记中断，其他受影响渠道在发送结束标记前保存日志。
- 失败日志中未发生上游计费或无法确定计费时，不虚构消费数值。

## 限制

旧日志没有保存原始 usage，已经漏记的积分无法从 token 数量准确恢复，未回填历史日志或账户累计值。
上游未返回单次积分时，也不使用账户余额前后差估算：并发请求、每日赠分和外部客户端消费都可能混入余额变化。
不同渠道积分单位和兑换规则不同，统计值沿用各渠道返回值，不意味着统一货币成本。
本次在线取样不能证明某渠道所有模型、所有响应均无积分字段；未成功取样和没有国际账号的部分以上述限制为准。
