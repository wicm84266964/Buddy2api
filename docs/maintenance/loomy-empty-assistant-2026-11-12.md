# Loomy 长历史中的独立思考消息

## 现象与证据

智能体在长会话中收到 502，网关对应尝试记录为
`RemoteProtocolError: Server disconnected without sending a response.`。
随后账号进入冷却，智能体快速重试出现 `No enabled account can serve this model right now`。
断连发生在约 8–15 秒，不是配置的 300 秒读取超时。

从本机智能体归档重建近似请求，在副本上诊断，未运行智能体工具或继续原项目任务。
副本不是失败请求的完整抓包：使用诊断系统提示和结尾，保留归档历史及 47 个工具定义。
因此这些结果不能证明历史上所有模型的报错都由同一原因造成。

- 原历史及裁剪后历史均未发现未匹配的工具调用或孤立工具结果。
- 本机网关对 DeepSeek 的长请求成功，实际输入 154755 tokens。
- 同一历史切换 Qwen，网关复现约 8 秒断连及 502。
- Qwen 更短的副本也返回 DashScope HTTP 400 参数错误，不能仅按长度解释。
- 历史包含 `content: null`、只有 `reasoning_content` 且无工具调用的 assistant 消息。
- 只删除 reasoning 字段、仍留下空 assistant：HTTP 400。
- 删除这些独立思考消息、保留其他回答与工具调用的 reasoning：重放成功，输入 93645 tokens。
  此变体第一次尝试也曾断连，因此上游瞬时断连仍需独立考虑。
- 给空 assistant 补诊断占位正文、保留原 reasoning 和历史长度：成功，输入 159642 tokens。
- 删除全部历史 reasoning 并移除空 assistant：成功，输入 61066 tokens。

## 修复范围

Loomy 构建上游请求时滤除只有 reasoning 的空 assistant 消息。
正常回答、工具调用、工具返回、拒绝消息及其 reasoning 均保留。
只构建新的 messages 列表，不修改调用方 payload；流式和非流式共用。
不把任意网络断连认定为上下文超限，也不修改用户预算或模型容量声明。

## 验证

`python -m pytest tests/test_loomy.py tests/test_loomy_request_timeout.py tests/test_context_budget.py -q`

44 passed。新增回归覆盖裁剪后从独立思考消息开始的历史、两种 stream 参数、
工具调用/返回及 reasoning 保留、拒绝消息保留与原 payload 不被修改。

## 2026-11-12 复发调查：上游代理间歇失败

当前修复进程 PID 33236 上仍发生错误。日志 51465、51471（14:06:52、14:07:04）
为上游返回的 `502 Bad Gateway` HTML，页脚 `xunfei`，耗时 6.2 / 4.8 秒。
紧接着的账号冷却导致快速重试得到 503。前一成功日志 51464 输入 70239 tokens。
智能体持久化记录显示最近压缩在 13:52:11，之后已有多轮成功；不能将该截图理解为压缩请求本身失败。

从更新后的归档构建诊断副本，保留摘要、73 条近期消息及 47 个工具定义，替换系统/结尾提示，
限制输出，不执行工具。过滤独立思考后估计输入 55523，成功响应实际输入 63944。
完全相同副本共四次直连请求：两次成功，两次响应头前 RemoteProtocolError；短请求也成功。
修改工具 ID 的副本也曾断连。没有证据确定上游内部断连原因，也未证明真实失败请求的每个字段无误。
这些结果证明存在相同请求的间歇失败，不能将本次故障解释为固定上下文阈值必然拒绝。

补充修复：Loomy 流式和非流式共用的上游连接，在响应头前 RemoteProtocolError 或 HTTP 502/503
时关闭失败响应，等待 0.5 秒，向同一账号原样重试一次。第一次失败记录 retry 日志且不计请求用量，
也不立即冷却账号；再次失败仍按原流程记录并处理。收到响应头后的流消费故障不重试，避免重复输出。
400、401、429、504 不经过此重试。该措施缓解瞬时故障，不能保证持续上游故障恢复。

新增回归覆盖连接关闭顺序、重试上限、非重试状态、流中断不重放，以及流式/非流式恢复时的
账号健康、失败日志、成功 token/积分统计。
