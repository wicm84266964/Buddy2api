# Loomy 长会话压缩与上游 504

2026-11-12 10:24 的日志 51205/51206 显示：非流式压缩请求等待约 154 秒后，Loomy 上游返回 `504 Gateway Time-out` HTML 页面（openresty）。这不是本地 300 秒读取超时。

Ant Code 在模型压缩失败后执行了本地压缩，记录 `lastStrategy=local`、`lastFallbackReason=GATEWAY_HTTP_ERROR`，因此界面仍显示“聊天内容已压缩”。但网关把上游 HTTP 504 计入账号冷却，紧接着的流式请求和重试无法选到唯一的 Loomy 账号，最终返回 503。

之前只排除了本地 `httpx.ReadTimeout` 的账号冷却，没有排除实际 HTTP 504。此前的短消息及压缩副本测试也不足以覆盖这次上游反向代理超时。

本轮修改：

- 非流式调用在内部改用上游 SSE，汇总内容、思考、工具调用与用量后返回普通 JSON；保留客户端非流式日志和一次计费。
- 内部 SSE 使用配置的响应读取超时，持续收到数据时允许完成较长的摘要。
- 实际 HTTP 504 不再触发账号冷却，HTML 超时页转换为明确的上游超时说明；其他连接、鉴权等错误保留原处理。
- 收集流必须完整结束，避免把半份摘要作为成功结果交给智能体。

完整回归 914 项通过，包括实际 HTTP 504 后仍可发起下一请求、SSE 分片工具调用与思考内容、分段积分用量，以及不完整响应拒绝作为成功摘要。

本地 8787 重启加载补丁后，使用 Ant Code 相同配置，对失败会话副本生成的 86664 字节非流式压缩请求进行实测：133.7 秒返回 HTTP 200，摘要 9207 字符，usage 返回 14 积分；立即发送短请求，2.2 秒返回 HTTP 200。未续跑真实项目任务。

该修改不能消除上游自身所有超时：若上游在首个事件之前即超时，仍会返回 504，但不会再仅因此导致后续请求无账号可用。
