# Buddy2api v2.2.23

修复 Loomy 长会话压缩超时后连续报“没有可用账号”、多渠道积分漏记，以及 Responses 流式结束时日志遗漏或误报中断的问题。

- Loomy 非流式聊天在内部接收上游 SSE，再汇总为普通 JSON 返回，降低长摘要等待完整响应时触发上游反向代理超时的风险；保留思考、工具调用、分段用量和积分，拒绝把不完整流作为成功结果。
- Loomy 非流式请求及账号测试读取网关响应超时设置，默认 300 秒，支持 5–600 秒；设置页将“上游响应超时”放在排队时间旁，明确区分两种等待。
- Loomy 本地读取超时和上游 HTTP 504 不再仅因此冷却整个账号，避免单个长请求超时后，其他请求连续报 `No enabled account can serve this model right now`；超时日志包含明确原因，上游 HTML 504 转为可读错误。
- Loomy、小浣熊、QwenWork 日志采集上游明确返回的 `credit` / `points_consumed`；QwenWork 合并流式分段用量，避免较早扣费字段被末尾 token 统计覆盖。
- Qoder 国内/国际收集 COSY 包装中的 usage，保留到 Chat 响应和日志；TraeWork 保留 token_usage 中明确返回的单次积分字段。上游未提供 token 时，Qoder 仍使用原有字符估算。
- Responses 的 JSON / SSE 用量转换保留积分扩展字段；新日志中未返回的积分显示“未返回”，与真实 0 区分，不影响账号累计数值。
- 修复流式客户端收到 `[DONE]` 即关闭时的处理顺序，避免 Loomy 将正常结束误记为中断，以及其他受影响渠道遗漏请求日志。Loomy、小浣熊、QwenWork 在读取失败时保留已收到的部分用量和积分。

历史日志中已经漏记的积分无法准确恢复，本版不回填，也不按 token 或余额变化推算单次消费。部分渠道和模型未返回单次积分；不同渠道积分不代表统一货币成本。内部流式接收不能保证消除上游所有超时，首个事件之前仍可能收到上游 504。

验证：Windows 本地完整测试 914 项通过，另运行 Python 语法编译；实际验证 Loomy 的 Chat Completions / Responses、流式 / 非流式四条链路，响应与日志积分一致。长会话副本压缩约 133.7 秒成功，立即发送短消息约 2.2 秒成功。

更新并重启服务后生效。

正式镜像：`ghcr.io/wicm84266964/buddy2api:v2.2.23`（`linux/amd64`）。正式发布同时更新 `latest`。
