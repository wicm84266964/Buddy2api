# Buddy2api v2.2.22

修复请求用量和失败日志遗漏、零余额账号无法刷新模型列表，并为一键更新增加 codeload 下载回退。

- Loomy 流式请求主动请求并记录上游 Token 用量、真实结束原因；连接中断时保留已收到的用量并记录失败。历史缺失用量无法准确回填。
- 小浣熊补充流式用量请求，合并分段用量；QClaw 保留适配代码修复相同的写零问题（渠道仍已停用）。
- Qoder 国内/国际日志按客户端实际请求记录流式标记，正确记录工具调用结束原因。Qoder Token 仍为字符估算，输入用量仍不可得。
- 模型列表刷新不再受聊天余额门槛限制，解决 TraeWork 等渠道余额为零时显示 `no usable account`；聊天请求的额度检查、禁用账号检查保持有效。
- Chat Completions 和 Responses 增加统一失败日志兜底，覆盖 HTTP 错误、网关转换异常和 SSE 流内错误；避免重复记录已有终态失败，不重复累计用量。
- 常规版本源都失败时，从 `codeload.github.com` 源码包读取版本；Git 拉取因连接失败或超时无法更新时，尝试源码包更新。
- 源码包更新校验版本、路径与仓库，保存更新前备份；保护本地配置、数据库和未跟踪文件，遇到本地修改、提交或冲突停止，写入异常时回滚。Git 历史保持不变，后续一键更新继续使用源码包方式。

codeload 回退仍需要能访问 `codeload.github.com`，依赖安装仍使用原有 pip 流程。Docker 和非 Git 安装保持原有更新方式。

验证：Windows 本地完整测试 861 项通过；发布前另运行 Python 语法编译。更新流程测试使用临时 Git 仓库验证回退、文件保护、连续更新和写入失败回滚；已实际验证 codeload 源码包下载与版本解析。

更新并重启服务后生效。

正式镜像：`ghcr.io/wicm84266964/buddy2api:v2.2.22`（`linux/amd64`）。正式发布同时更新 `latest`。
