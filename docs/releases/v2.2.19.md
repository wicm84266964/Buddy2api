# Buddy2api v2.2.19

发布日期：2026-11-06

本补丁整合社区 PR #138，修复额度耗尽账号的重复重试和工具调用流误报 502，并新增默认关闭的主动限流设置。

## 修复

- **账号冷却（[#138](https://github.com/wicm84266964/Buddy2api/pull/138)）**：冷却结束后保留连续失败次数，退避可逐步延长至 300 秒，成功后清零，长时间无失败后衰减。读取上游额度重置时间，最长冷却一小时，减少已知额度耗尽账号的无效重试。
- 补齐 `UTC+8`、`UTC+0`、`UTC-5`、分钟偏移和 UTC 时间格式的解析与校验；并发失败不会缩短已记录的额度冷却。
- **工具调用（[#141](https://github.com/wicm84266964/Buddy2api/issues/141)）**：续传分片中的空串 `id` / `type` 按缺省字段处理，沿用首帧有效身份，避免并行工具调用整轮 502。非字符串 ID、冲突 ID 和不完整调用仍会被拒绝。
- 上下文裁剪重试前关闭旧响应，避免并发限制为 1 时等待自己释放名额；客户端取消时关闭替换后的响应。
- 及时关闭 TraeWork 已预读的上游流，覆盖正常完成、途中取消和输出开始前关闭，防止连接和并发名额泄漏。

## 主动限流

响应 [#140](https://github.com/wicm84266964/Buddy2api/issues/140)，在「设置 → 主动限流」增加：

| 设置 | 默认 | 范围 |
|---|---|---|
| 每账号最小请求间隔 | 0 秒（关闭） | 0–600 秒 |
| 每账号最大并发 | 0（不限制） | 0–100 |
| 最长排队时间 | 120 秒 | 1–600 秒 |

- 所有渠道的 Chat Completions / Responses、流式 / 非流式、内部重试和账号测试共用每账号的限流名额；登录、签到和额度查询不占名额。
- 按账号先进先出排队，不同账号相互独立；每账号最多 256 个等待请求。排队超时可尝试其他候选账号；全部繁忙时返回本地 429，已经开始的 SSE 以错误事件结束，不将账号标成失效。
- 请求取消或上游结束后释放名额。排队期间账号若进入额度冷却，不再向它发送请求。
- 保存后生效；可先尝试最小间隔 5 秒、最大并发 1。间隔和并发都设为 0 即关闭。

计数仅保存在当前网关进程内，重启后清空。独立网关进程不共享计数。降低调用速度不能保证避免上游 token、模型或累计用量限制。关闭跨渠道故障转移时，本地排队错误直接返回。

## 升级与验证

无需数据库迁移。主动限流默认关闭，升级后需手动开启并保存。

本地完整测试 **790 项通过**；Python 编译、7 个 Vue 模板编译和 2 段内联脚本语法检查通过。模拟上游验证覆盖流式/非流式、并行工具调用、冷却退避、排队取消、超时、上下文恢复及连接释放；未调用真实账号做额度耗尽测试。设置页在隔离数据库中完成保存和刷新验证。发布提交须通过 GitHub CI。

正式镜像：`ghcr.io/wicm84266964/buddy2api:v2.2.19`（`linux/amd64`）。正式发布流程同时更新 `latest`。发布版本和镜像不会自动重启已有实例，请在正在执行的任务结束后更新并重启服务。
